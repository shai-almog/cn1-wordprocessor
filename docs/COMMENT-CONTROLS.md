# Comment controls acceptance

Review now includes Previous comment and Next comment. They follow paragraph/table-cell order rather than creation order, include resolved threads and wrap at either end. Navigation places the caret at the comment start, matching the pinned Wordcraft commands. Go to in the Comments dialog still selects the whole anchored range. Navigation leaves document content, revision and undo history unchanged.

The Comments dialog can edit the thread text or any reply. Saving preserves its author, range and resolved state; Cancel preserves the original text. Each saved edit is undoable. Reply controls have distinct accessible labels, and the comment action row wraps on narrow layouts. DOCX import now retains leading blank paragraphs in comment text, alongside interior and trailing blank lines.

Six new regression tests cover navigation through body/cell stories, wraparound, reversed selection focus, resolved threads, empty documents, edit metadata/undo, invalid input without selection mutation, command argument validation and native/DOCX blank-line persistence. The Java 8 reactor passes 356 tests with no failures, errors or skips.

Native Maven/ParparVM acceptance passes 215 checks: Linux 131, Mac 42, and iPhone simulator 42. Each platform runs 22 comment ribbon/dialog checks plus comparison and Mailings regressions; Linux also runs keyboard, native dialog input, navigation, typing and Unicode grapheme checks. Phone screenshots additionally verify the comment action layout and edit-reply sheet. All original XML and recipient state were restored, recovery settled, and task apps/containers stopped.

Twelve paired DOCX checks cover edited root/reply text and blank-line preservation in both directions. Twenty navigation artifact checks cover five next/previous scenarios in both apps plus reopening with the other reader; inserted markers verify the resulting body/cell caret positions. All 59 existing paired document cases and 20 review interchange checks pass. These are scoped behavior and artifact checks, not full visual or Word fidelity certification.

The first Mac acceptance runner used null for a body selection, while the MCP represents it with block/row/column -1. Its 18 completed checks are retained separately; the corrected final 22-check run passed. A phone layout inspection needed a second cleanup pass because mobile child and parent dialogs reuse window 0; the corrected helper refreshes the window list after each close. Exact original XML was verified after both the repair and a successful rerun. Linux's offline build attempt lacked a Maven plugin; its successful retry used network access only for build dependencies. Two display-launch attempts failed before launching the app; the final local X11 run is the accepted evidence.

Framework source remains the merged 008f9ece baseline with the separately reviewed Mac #6027 and Linux #6026 patches. Their live status is preserved with this checkpoint. At inspection, neither had unresolved review threads; Mac had no failing checks, while Linux's Hugo website job failed with a local port collision and was rerun alone. Pending jobs and the website rerun are not counted as green.

Exact source hashes, native bundles, build logs, fixtures and final reports are in `artifacts/parity-20261016-comment-controls`; see `comment-controls-acceptance.json`. The Linux review binary uses GNU 11.4.0 with RelWithDebInfo and retained debug information; the prior checkpoint used Clang/LLVM. Its larger byte count is therefore not a matched size regression. The review binaries have different debug/build settings, so their stored byte counts are provenance rather than matched release-size benchmarks. No new startup/RSS or language/framework superiority claim is made.

Remaining limitations include cross-cell and note/margin-story comment ranges, rich comment-body formatting, timestamps/mentions, full Word UI/rendering fidelity and current-source Android/browser/Windows acceptance. Cross-platform physical input, advanced document features and final matched performance work remain incomplete. Full Wordcraft parity is not certified.
