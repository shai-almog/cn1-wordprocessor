# Status and known limitations

The app builds from one Java source for macOS, Linux, Windows, iOS, Android and the browser.
It implements the 487 working rows of Wordcraft's 502-row feature catalog (the other 15 are
stubs in Wordcraft too); each row was replayed in the native Mac app ([catalog matrix](acceptance-matrix.json),
[native check results](native-certification.json)). That check proves the native app matches
this app's JVM behavior and that every control has an observable effect. It is not a
byte-for-byte comparison with Wordcraft's output.

Performance numbers come from CI only (`.github/workflows/metrics.yml`); see the README.
Format coverage and its limits are in [FORMATS](FORMATS.md).

## Known limitations

Where a limitation also exists in Wordcraft, the row says so. Everything else is a gap we are closing.

| Area | Limitation |
| --- | --- |
| Word XML import | Flat OPC opens fully through the DOCX reader. Word 2003 XML (`w:wordDocument`) imports body text, properties, styles, lists, hyperlinks, embedded pictures, text boxes, headers/footers, footnotes/endnotes and comments by converting them to DOCX parts; VML floating positions are lost (inline), other VML shapes and linked pictures are dropped with warnings. |
| DOCX | Custom/composite numbering labels, theme fonts and colors, advanced section, header/footer and field content, floating/cropped/rotated pictures, anchored objects and nested tables are approximated or unsupported. Real-world round trips can lose layout detail. |
| Formats Wordcraft has | WMF/EMF pictures render as bitmaps without their text records (Wordcraft also skips metafile text). Zotero integration: see the Zotero row. ODT carries one page style and no comments or tracked changes (Wordcraft drops those too). `.doc` import covers comments, bookmarks, insert/delete revisions, merged and nested cells and main-text floating pictures, preset shapes and text boxes; header floats, grouped shapes, freeforms and formatting revisions are not imported (docs/FORMATS.md). |
| Zotero | References > Zotero (Add/Edit Citation, Add/Edit Bibliography, Refresh, Document Preferences, Unlink Citations) speaks Zotero's word-processor wire protocol on 127.0.0.1:23116 through Codename One sockets. Verified only against a scripted fake Zotero in unit tests, not yet against a running Zotero desktop app or in the native app; ports where Codename One sockets are unsupported (browser) report an error. Citations are atomic plain-text fields in top-level body paragraphs: no citations in table cells, footnotes or endnotes, so footnote/endnote (note) citation styles are refused; rich (RTF/HTML) results keep bold, italic, underline, superscript/subscript and small caps as formatted runs (with entries as separate paragraphs) when Zotero inserts text, and a citation or bibliography field keeps its result's formatted runs (bold, italic, underline, small caps, superscript/subscript; drawn per run, saved to DOCX as formatted runs between the field's separate and end marks and read back, and in the native file/clipboard) as Wordcraft keeps them between its field marks, though the field stays one atomic object for editing (no caret inside, unlike Wordcraft); the bibliography is saved to DOCX as one Bibliography paragraph per entry inside the field and a Word bibliography field spanning paragraphs is reassembled on import, but in the app it is one field in one paragraph with entries shown space-separated (Wordcraft shows a paragraph per entry); Document_setBibliographyStyle is applied as Wordcraft's set_bibliography_style does (a Bibliography paragraph style: body indent, first-line/hanging indent, line spacing as a multiple of 240ths clamped 0.5-5, no space before, entry spacing after, left tab stops; twips clamped to +-22in), and Field_setText on a bibliography field gives its paragraph that style, which DOCX export writes as a w:style. Gap vs Wordcraft: Wordcraft's fields are ranges holding arbitrary formatted content, so mixed formatting and one paragraph per bibliography entry survive inside the field; here they do not (see above); placeholder conversion, Add Note and document import/export transfer are unsupported. Each Zotero edit is its own undo step. |
| Typography | Glyph shaping on screen comes from the platform text renderer. Bidi ordering implements full UAX #9 levels (explicit embeddings, overrides and isolates, bracket pairing, L1 reset) in BidiBridge, an extended copy of Codename One's BidiUtil pending upstream adoption (codenameone/CodenameOne#6065); character types use coarse script ranges rather than the full Unicode database, and it is checked against hand-written known answers, not the full BidiCharacterTest suite. Tabbed lines reorder per tab segment. Decimal tabs align on a period only (as in Wordcraft). |
| PDF | Subset TrueType fonts and CFF fonts (charstring subset re-written as a CID-keyed FontFile3/CIDFontType0C; CFF2 faces embedded whole as FontFile3/OpenType), bundled Hebrew/Arabic fallback then installed-font fallback (TrueType, CFF and CFF2 faces) ranked per script, RTL, OpenType GSUB/GPOS shaping (ligatures, Arabic joining, cursive attachment, mark positioning; Indic reordering, split matras, reph and conjuncts for Devanagari, Bengali, Gurmukhi, Gujarati, Oriya, Tamil, Telugu, Kannada and Malayalam; Thai/Lao sara am decomposition; Khmer coeng/pre-base vowel and Myanmar medial Ra/pre-base vowel/kinzi reordering), kerning, links, outline and basic tags are exported. Checked against installed macOS Sangam MN fonts and synthetic tables, not yet against Wordcraft output per script. Not yet: Hangul jamo and USE-script shapers, CFF local/global subroutine subsetting (subroutines are copied whole), AAT-only fonts (Malayalam MN/Sangam MN, Thai system fonts have no GSUB, so only cmap glyphs and hmtx positions), Telugu ZWJ reph. See [FORMATS](FORMATS.md). |
| Proofing languages | Runs are proofed in their w:lang language (Review > Language sets it): English uses the bundled word list; Polish and Portuguese use a system-installed Hunspell `pl_PL`/`pt_BR`/`pt_PT` pair (none bundled, as in Wordcraft) with Polish/Portuguese grammar rules (repeated word, spacing, doubled punctuation, sentence capital, Polish missing comma before `że`/`który`); other languages get no marks. The Hunspell reader handles PFX/SFX, cross product, AF, MAP/REP/TRY but not twofold suffixes, compounding or ICONV, so real SJP/VERO dictionaries will over-flag some forms; `we`/`ze` and Wordcraft's fuller Polish/Portuguese suggestion tuning are missing; it has only been exercised with synthetic test dictionaries, not real installed ones or on device. Bulgarian (hyphenation only in Wordcraft) is unproofed. |
| Editing | Mixed body/table selections, nested table editing, cross-cell and note-story comment ranges, and table-cell proofing are unsupported. The layout engine re-paginates the whole document after an edit rather than only the changed suffix (Wordcraft does the same). Undo history keeps 500 steps (as Wordcraft), bounded by count rather than memory. |
| Accessibility | The document is exposed to screen readers through Codename One accessibility, but this has not been verified in a live VoiceOver, Narrator or Orca session. |
| Speech and accessibility checks | Read Aloud and Dictate (Tools menu and a Review > Speech ribbon group) use Codename One TextToSpeech and SpeechRecognizer through the Speech port and show a not-available message where the port reports no support. Read Aloud follows Wordcraft's player (crates/ui-egui/src/read_aloud.rs, engine speech.rs): it queues the sentences from the caret to the end (abbreviation- and initial-aware splitting, long sentences split at 600 characters), selects the sentence being read, and has previous / pause-resume / next / stop controls with a "Sentence i / n", Paused, Finished or Stopped status in the Speech group, plus a persisted "Skip citations" option (default on, as in Wordcraft) that leaves out Zotero, Mendeley, EndNote and Word citation fields and the bibliography and tidies the gaps they leave. All of it is the `review.readAloud` command (actions start, next, previous, pause, resume, playPause, current, stop). The controls are ribbon buttons, not Wordcraft's floating player window. TextToSpeech has no completion callback, so Read Aloud advances after an estimated speaking time (Wordcraft's 180 words per minute at 1x) and can drift from the real voice; pause stops the voice and resume restarts the current sentence. The reading speed (0.5x to 3x as in Wordcraft, offered as 0.5/0.75/1/1.25/1.5/1.75/2/2.5/3x steps rather than a 0.05-step slider, persisted in preferences) sets both the TextToSpeech rate and that estimate; how faithfully each platform voice honors the rate is unverified. Neither has been verified with live audio on any platform. Check Accessibility reports missing title and alt text, heading order, empty headings, tables without header rows, text contrast below 4.5:1, vague link text, repeated blanks and runs of empty paragraphs used for spacing; its results pane jumps to the reported paragraph. It does not check floating-object reading order, merged table cells or color-only meaning. |
| Platforms | Linux and Windows builds are produced and benchmarked by CI but have had little hands-on desktop use. Android and iOS were exercised on the emulator and simulator, not physical devices. The browser build has no live debugging channel. |
| Charts and SmartArt | Imported charts keep only cached data, type, title, legend and value labels (no stacking, styles, axis formats or combination groups); edited charts are saved without an embedded workbook. Wordcraft has the same chart limits. Imported SmartArt is drawn from Word's saved drawing until edited, then re-laid out with a basic layout. SmartArt editing matches Wordcraft's command set (crates/engine/src/cmd/smart_art.rs): insert.smartArt with Wordcraft's eight layouts (basicList/list, process, cycle, hierarchy, pyramid, radial, matrix, venn), smartArt.items/textPane (outline, levels 0-7, at most 100 items), addShape (after an item and its sub-items, or below as a sub-item), promote/demote (moving the item's sub-items along, refusing a demote without a preceding item at its level), layout, colors (accent1-6, colorful) and reset, each one undo step, plus smartArt.get. The UI is Insert > SmartArt: a layout picker, or with a SmartArt selected a SmartArt Design dialog (layout, colors, an editable Text Pane, Add Shape / Add Shape Below / Promote / Demote / Reset Graphic), not a contextual ribbon tab or Wordcraft's preview-thumbnail picker. Created or edited SmartArt is saved as real diagram parts as Wordcraft does (crates/docx/src/smart_art.rs): data model, a layout definition named by Wordcraft's built-in layout id, the flat quick style, colors, and a cached `dsp:drawing` Word displays; tests re-read all eight layouts from those parts alone (layout, items, colors and the cached shapes). Limits: the cached drawing holds the node shapes and process arrows but not hierarchy/radial connector lines or cycle rings, and it has not been checked by opening in Word. |
| Equations | Office Math is imported, drawn built-up and round-tripped, inline `m:oMath` is an inline object on the text line (baseline aligned, never wraps, caret steps over it as one unit; copy/paste, undo, DOCX round trip and PDF), `m:oMathPara` stays a display block, Insert > Equation offers Wordcraft's 14 built-in equations (on an empty line display, in text inline), and LaTeX `$...$`, `\(...\)`, `\[...\]`, `$$...$$` and equation environments import as inline/display equations. In-place structure editing ported from Wordcraft's `math_edit.rs` (`EquationEditor`, headless tests in `EquationEditorTest`): a caret inside inline and display equations that arrows across slots in reading order (fraction numerator/denominator, scripts and pre-scripts, radical degree/base, n-ary limits/operand, delimiters, function name/argument, limits, accents, boxes, matrix cells by row/column, equation-array rows), Up/Down into stacked slots, Home/End per slot then equation, Tab/Shift+Tab between empty slots, typing and Backspace/Delete inside slots (Backspace at a slot start dissolves the structure, empty structures are removed), Math AutoCorrect (Wordcraft's 324 `\name` entries plus `\doubleX`/`\scriptX`/`\frakturX`) and build-up of linear input on space/relations/Enter/leaving a slot, normal-text mode; an Equation contextual ribbon tab (Edit in Place, Done, Wordcraft's 11 Structures galleries with their 223 templates, its 8 Symbols sets); `equation.edit` and `equation.gallery` commands; every edit is one undo step and is saved through the existing DOCX/PDF paths. Still missing versus Wordcraft: entering an equation by arrowing or clicking into it (here it is the ribbon's Edit in Place, ending with Esc/clicking away or arrowing out), selection of a range inside an equation, typing is one undo step per keystroke rather than grouped, Wordcraft's per-structure context actions (`structure_actions`: insert matrix rows, change script kind...), LaTeX-mode build-up, `#` numbering on Enter, forced limit placement for some templates, seven bracket templates insert as linear text (see FORMATS.md), ink math, and fine OMML formatting survives only while the equation is unedited. The in-equation caret and ribbon tab are covered by headless tests only; no simulator UI test drives them yet. See FORMATS.md. |
| Recovery | Crash recovery is stored unencrypted, so password-protected documents get no recovery copy. Wordcraft's recovery is unencrypted too. |
| Releases | macOS builds are signed with Developer ID; notarization can lag, in which case the DMG is not stapled. Windows and Linux packages are unsigned. |
| Automation | The SDK and macro API are provisional (`0.1.0-SNAPSHOT`) with no compatibility policy yet. |
