# Status and known limitations

The app builds from one Java source for macOS, Linux, Windows, iOS, Android and the browser.
It implements the 487 working rows of Wordcraft's 502-row feature catalog (the other 15 are
stubs in Wordcraft too); each row was replayed in the native Mac app ([catalog matrix](acceptance-matrix.json),
[native check results](native-certification.json)). That check proves the native app matches
this app's JVM behavior and that every control has an observable effect. It is not a
byte-for-byte comparison with Wordcraft's output.

Performance numbers come from CI only (`.github/workflows/metrics.yml`); see the README.
Format coverage and its limits are in [FORMATS](FORMATS.md).

## Known limitations

Where a limitation also exists in Wordcraft, the row says so. Everything else is a gap we are closing.

| Area | Limitation |
| --- | --- |
| Word XML import | Flat OPC opens fully through the DOCX reader. Word 2003 XML (`w:wordDocument`) imports body text, properties, styles, lists, hyperlinks, embedded pictures, text boxes, headers/footers, footnotes/endnotes and comments by converting them to DOCX parts; VML floating positions are lost (inline), other VML shapes and linked pictures are dropped with warnings. |
| DOCX | Custom/composite numbering labels, theme fonts and colors, advanced section, header/footer and field content, floating/cropped/rotated pictures, anchored objects and nested tables are approximated or unsupported. Real-world round trips can lose layout detail. |
| Formats Wordcraft has | WMF/EMF pictures render as bitmaps without their text records (Wordcraft also skips metafile text). Zotero integration: see the Zotero row. ODT carries one page style and no comments or tracked changes (Wordcraft drops those too). `.doc` import covers comments, bookmarks, insert/delete revisions, merged and nested cells and main-text floating pictures, preset shapes and text boxes; header floats, grouped shapes, freeforms and formatting revisions are not imported (docs/FORMATS.md). |
| Zotero | References > Zotero (Add/Edit Citation, Add/Edit Bibliography, Add Note, Refresh, Document Preferences, Unlink Citations) speaks Zotero's word-processor wire protocol on 127.0.0.1:23116 through Codename One sockets. Verified only against a scripted fake Zotero in unit tests, not yet against a running Zotero desktop app or in the native app; ports where Codename One sockets are unsupported (browser) report an error. As in Wordcraft, citations live in body paragraphs, table cells, footnotes and endnotes: Document_getFields lists a cell's fields at its table and a note's fields at its reference mark with the note's number; with a note citation style Document_insertField puts the citation in a new footnote or endnote, and Document_convert/Field_convert move a citation between the text, footnotes and endnotes keeping its id (a note left empty is removed). Document_convertPlaceholdersToFields turns `https://www.zotero.org/?<id>` placeholder links into fields holding the link text. Document_importDocument/exportDocument are refused with Wordcraft's message (the fields are already stored the way Word keeps them). As in Wordcraft, Field_select on a note's citation moves the selection into the note's story over the citation (the editor surface does not draw a selection inside the note area yet), and Document_cursorInField then reports it. DOCX round trips of citations inside cells and notes are tested; opening a document converts atomic fields to ranges and repairs unbalanced marks in table cells and notes as well as the body, and a bibliography inserted in a note takes the Bibliography style. As in Wordcraft (FieldStart/FieldEnd), a Zotero field is a range: a start mark holding the code, the result as ordinary formatted text, and an end mark, so the caret moves and types inside a citation (Document_cursorInField reports the caret anywhere from the start mark to the end of its text) and a bibliography is one Bibliography-style paragraph per entry in the app; Field_setText replaces the text between the marks with the rich runs (bold, italic, underline, small caps, superscript/subscript; newlines start paragraphs), Field_getText returns that text with entries joined by newlines, Field_delete/Field_select cover both marks, Field_removeCode drops the marks and keeps the text. Documents opened with older atomic Zotero fields (earlier native files, DOCX import) are converted to ranges when loaded into the editor. The marks are zero-width: arrow keys, word moves, Backspace and Delete cross a mark together with the visible character beyond it (never stopping on or deleting a mark alone), so arriving from outside a citation keeps the caret outside and typing there stays outside; a deletion that takes one mark repairs the pair (a deleted start drops its end and leaves plain text, a deleted end is re-added at the end of the start's paragraph), and justified lines containing marks are justified. DOCX writes the marks as begin/instrText/separate and end around the paragraphs' own runs (one paragraph per bibliography entry) and a Word bibliography field spanning paragraphs is read back; Document_setBibliographyStyle is applied as Wordcraft's set_bibliography_style does (a Bibliography paragraph style: body indent, first-line/hanging indent, line spacing as a multiple of 240ths clamped 0.5-5, no space before, entry spacing after, left tab stops; twips clamped to +-22in), and Field_setText on a bibliography gives each entry paragraph that style, which DOCX export writes as a w:style. Each Zotero edit is its own undo step. |
| Typography | Glyph shaping on screen comes from the platform text renderer. Bidi ordering implements full UAX #9 levels (explicit embeddings, overrides and isolates, bracket pairing, L1 reset) in BidiBridge, an extended copy of Codename One's BidiUtil pending upstream adoption (codenameone/CodenameOne#6065); character types use coarse script ranges rather than the full Unicode database, and it is checked against hand-written known answers, not the full BidiCharacterTest suite. Tabbed lines reorder per tab segment. Decimal tabs align on a period only (as in Wordcraft). |
| PDF | Subset TrueType fonts and CFF fonts (charstring subset re-written as a CID-keyed FontFile3/CIDFontType0C; CFF2 faces embedded whole as FontFile3/OpenType), bundled Hebrew/Arabic fallback then installed-font fallback (TrueType, CFF and CFF2 faces) ranked per script, RTL, OpenType GSUB/GPOS shaping (ligatures, Arabic joining, cursive attachment, mark positioning; Indic reordering, split matras, reph and conjuncts for Devanagari, Bengali, Gurmukhi, Gujarati, Oriya, Tamil, Telugu, Kannada and Malayalam; Thai/Lao sara am decomposition; Khmer coeng/pre-base vowel and Myanmar medial Ra/pre-base vowel/kinzi reordering), kerning, links, outline and basic tags are exported. Checked against installed macOS Sangam MN fonts and synthetic tables, not yet against Wordcraft output per script. Hangul follows HarfBuzz's Hangul shaper (L V T jamo and LV+T composed to the font's precomposed syllable, otherwise ljmo/vjmo/tjmo; checked against hb-shape with Apple SD Gothic Neo), Telugu forms its reph only with an explicit ZWJ (checked against hb-shape with Kohinoor Telugu), and CFF subsets keep only the global/local subroutines the kept charstrings reach (the rest become a bare return, so numbering is unchanged). The Universal Shaping Engine (ported from harfrust: category table, syllable machine, reph/pre-base recording, reordering, dotted circles) shapes USE scripts, matching hb-shape glyph for glyph with the installed Noto Javanese, Balinese, Brahmi, Batak, Cham, Sundanese, Lepcha and Buginese fonts, and the Malayalam dot reph moves after the main consonant (matching hb-shape with the macOS Sama and Baloo Chettan Malayalam faces). AAT shaping as harfrust's aat module: a face with `morx` but no GSUB script for the run is shaped by its `morx` chains (rearrangement, contextual, ligature, noncontextual and insertion subtables through the AAT state machine driver; each chain's default flags) and positioned with `kerx` formats 0/2 (else the `kern` table, never GPOS, marks keep their advances) and `trak` at the run's point size, matching hb-shape glyph for glyph and advance for advance with macOS Kailasa (Tibetan), Malayalam MN and Malayalam Sangam MN (Ka+virama+Ka conjunct, pre-base vowel signs, ra-sign) and Silom (Thai); subsets keep the glyphs morx produces because they are built from the shaped ids. Not yet: `kerx` state-machine formats 1/4/6, morx feature selection beyond chain defaults, vertical AAT. Sinhala MN/Sangam MN list `sinh` in GSUB, so HarfBuzz and this shaper use GSUB there. USE also gives Mongolian, N'Ko, Phags-pa, Adlam, Hanifi Rohingya, Mandaic, Manichaean, Psalter Pahlavi, Sogdian, Old Uyghur and Chorasmian Arabic joining forms from harfrust's Unicode 17 joining data, and Syriac takes HarfBuzz's Arabic shaper with its Alaph state machine (fin2/fin3/med2); GPOS runs in logical order and RTL output puts marks before their base as HarfBuzz (matching hb-shape with the Noto Syriac, Mandaic, Manichaean, Psalter Pahlavi, N'Ko and Adlam faces); GSUB alternate lookups pick the first alternate, keeps the pre-reordering features inside a syllable (F_PER_SYLLABLE), and can skip dotted circles (HarfBuzz's DO_NOT_INSERT_DOTTED_CIRCLE buffer flag). See [FORMATS](FORMATS.md). |
| Proofing languages | Runs are proofed in their w:lang language (Review > Language sets it): English uses the bundled word list; Polish and Portuguese use a system-installed Hunspell `pl_PL`/`pt_BR`/`pt_PT` pair (none bundled, as in Wordcraft) with Polish/Portuguese grammar rules (repeated word, spacing, doubled punctuation, sentence capital, Polish missing comma before `że`/`który`); other languages get no marks. Polish also gets Wordcraft's `we`/`ze` rule (`we wtorek`, `ze szkoły`, `ze mną`). The Hunspell reader handles PFX/SFX, cross product, AF, continuation classes (twofold suffixes, a suffixed form under a prefix), NEEDAFFIX, ONLYINCOMPOUND, compounding by COMPOUNDFLAG/COMPOUNDBEGIN/MIDDLE/END with COMPOUNDMIN and COMPOUNDWORDMAX, ICONV/OCONV and MAP/REP/TRY (Wordcraft rejects dictionaries using compounding or ICONV); COMPOUNDRULE and the CHECKCOMPOUND* restrictions are not implemented. Suggestions follow Wordcraft's Polish/Portuguese ranking: case, adding a diacritic, REP, a missing space (cheap next to the language's short leading/trailing words), one typo, then a scan of roots within two typos where a diacritic slip costs half (roots only, not their affixed forms). It has only been exercised with synthetic test dictionaries, not real installed ones or on device. Bulgarian (hyphenation only in Wordcraft) is unproofed. |
| Editing | Tables nest in cells as in Wordcraft (its paths nest three indexes per level): cells hold paragraphs and tables, the cell context is recursive (`Session.cellPath`/`enterCellPath`/`enterNestedCell`/`leaveCellLevel`), Insert Table, quick tables and text-to-table work inside a cell, Tab, row/column/merge operations, cell-range selection, typing and undo work at any depth, the layout places nested tables inside their cell (lines and boxes carry the nested path) and the editor hit-tests, draws the caret and drags cell ranges in them; native XML, DOCX (`w:tc/w:tbl`), ODT and HTML round-trip them (Markdown and RTF export flatten them; `.doc` import is unchanged). A nested table is laid out as a unit inside its cell row and is not split across pages by itself. Mixed body/table selections (Wordcraft's stream selection runs from body text into or over a table for copy, delete and formatting) are unsupported: a selection is either body text or one cell's text or whole cells. Comment ranges follow Wordcraft's stream order: Review > New Comment on selected cells anchors one range from the first cell's start to the last cell's end, and a range may run from body text into a table; such ranges are highlighted in reading order, survive edits (body endpoints move with the edit, cell endpoints are clamped) and round-trip through DOCX, and selecting one selects its cells. Footnote and endnote stories can be edited as a story (`Session.enterNote`, used by Field_select and comment selection), so comments are anchored, highlighted and round-tripped through DOCX footnotes/endnotes; while a note story is entered the editor draws its caret and selection in the note area and clicks there place the caret in the story. Table cells are proofed: the marks are drawn in cells and Review > Spelling (`review.spelling` check/next/ignore/change) walks cell paragraphs, entering the cell to select or change an issue. The layout engine re-paginates the whole document after an edit rather than only the changed suffix (Wordcraft does the same). Undo history keeps 500 steps (as Wordcraft), bounded by count rather than memory. |
| Accessibility | The document is exposed to screen readers through Codename One accessibility, but this has not been verified in a live VoiceOver, Narrator or Orca session. |
| Speech and accessibility checks | Read Aloud and Dictate (Tools menu and a Review > Speech ribbon group) use Codename One TextToSpeech and SpeechRecognizer through the Speech port and show a not-available message where the port reports no support. Read Aloud follows Wordcraft's player (crates/ui-egui/src/read_aloud.rs, engine speech.rs): it queues the sentences from the caret to the end (abbreviation- and initial-aware splitting, long sentences split at 600 characters), selects the sentence being read, and has previous / pause-resume / next / stop controls with a "Sentence i / n", Paused, Finished or Stopped status in the Speech group, plus a persisted "Skip citations" option (default on, as in Wordcraft) that leaves out Zotero, Mendeley, EndNote and Word citation fields and the bibliography and tidies the gaps they leave. All of it is the `review.readAloud` command (actions start, next, previous, pause, resume, playPause, current, stop). The controls are ribbon buttons, not Wordcraft's floating player window. TextToSpeech has no completion callback, so Read Aloud advances after an estimated speaking time (Wordcraft's 180 words per minute at 1x) and can drift from the real voice; pause stops the voice and resume restarts the current sentence. The reading speed (0.5x to 3x as in Wordcraft, offered as 0.5/0.75/1/1.25/1.5/1.75/2/2.5/3x steps rather than a 0.05-step slider, persisted in preferences) sets both the TextToSpeech rate and that estimate; how faithfully each platform voice honors the rate is unverified. Neither has been verified with live audio on any platform. Check Accessibility reports missing title and alt text, heading order, empty headings, tables without header rows, text contrast below 4.5:1, vague link text, repeated blanks and runs of empty paragraphs used for spacing; its results pane jumps to the reported paragraph. It does not check floating-object reading order, merged table cells or color-only meaning. |
| Platforms | Linux and Windows builds are produced and benchmarked by CI but have had little hands-on desktop use. Android and iOS were exercised on the emulator and simulator, not physical devices. The browser build has no live debugging channel. |
| Charts and SmartArt | Imported charts keep only cached data, type, title, legend and value labels (no stacking, styles, axis formats or combination groups); edited charts are saved without an embedded workbook. Wordcraft has the same chart limits. Imported SmartArt is drawn from Word's saved drawing until edited, then re-laid out with a basic layout. SmartArt editing matches Wordcraft's command set (crates/engine/src/cmd/smart_art.rs): insert.smartArt with Wordcraft's eight layouts (basicList/list, process, cycle, hierarchy, pyramid, radial, matrix, venn), smartArt.items/textPane (outline, levels 0-7, at most 100 items), addShape (after an item and its sub-items, or below as a sub-item), promote/demote (moving the item's sub-items along, refusing a demote without a preceding item at its level), layout, colors (accent1-6, colorful) and reset, each one undo step, plus smartArt.get. The UI is Insert > SmartArt: a layout picker, or with a SmartArt selected a SmartArt Design dialog (layout, colors, an editable Text Pane, Add Shape / Add Shape Below / Promote / Demote / Reset Graphic), not a contextual ribbon tab or Wordcraft's preview-thumbnail picker. Created or edited SmartArt is saved as real diagram parts as Wordcraft does (crates/docx/src/smart_art.rs): data model, a layout definition named by Wordcraft's built-in layout id, the flat quick style, colors, and a cached `dsp:drawing` Word displays; tests re-read all eight layouts from those parts alone (layout, items, colors and the cached shapes). Limits: the cached drawing holds the node shapes and process arrows but not hierarchy/radial connector lines or cycle rings, and it has not been checked by opening in Word. |
| Equations | Office Math is imported, drawn built-up and round-tripped, inline `m:oMath` is an inline object on the text line (baseline aligned, never wraps, caret steps over it as one unit; copy/paste, undo, DOCX round trip and PDF), `m:oMathPara` stays a display block, Insert > Equation offers Wordcraft's 14 built-in equations (on an empty line display, in text inline), and LaTeX `$...$`, `\(...\)`, `\[...\]`, `$$...$$` and equation environments import as inline/display equations. In-place structure editing ported from Wordcraft's `math_edit.rs` (`EquationEditor`, headless tests in `EquationEditorTest`): a caret inside inline and display equations that arrows across slots in reading order (fraction numerator/denominator, scripts and pre-scripts, radical degree/base, n-ary limits/operand, delimiters, function name/argument, limits, accents, boxes, matrix cells by row/column, equation-array rows), Up/Down into stacked slots, Home/End per slot then equation, Tab/Shift+Tab between empty slots, typing and Backspace/Delete inside slots (Backspace at a slot start dissolves the structure, empty structures are removed), Math AutoCorrect (Wordcraft's 324 `\name` entries plus `\doubleX`/`\scriptX`/`\frakturX`) and build-up of linear input on space/relations/Enter/leaving a slot, normal-text mode; an Equation contextual ribbon tab (Edit in Place, Done, Wordcraft's 11 Structures galleries with their 223 templates, its 8 Symbols sets); `equation.edit` and `equation.gallery` commands; typing in an equation is one grouped undo step until another edit (as Wordcraft's "Typing" group; caret moves keep the group), other edits one step each, all saved through the existing DOCX/PDF paths; clicking a display or inline equation enters it with the caret at the nearest slot position (Wordcraft's `equation_hit`); the Equation tab's Unicode / LaTeX toggle (`equation.inputFormat` unicode|latex, Wordcraft's `math_latex` session flag) switches build-up to LaTeX, read by `MathLatex` (a port of Wordcraft's `math_latex::parse_latex`: `\frac`, `\sqrt[n]`, scripts, big operators with limits and operands, `\left..\middle..\right`, matrix/cases/aligned environments, accents, over/underbraces, `\overset`/`\underset`, `\text`/`\mathrm`/`\mathbb`/`\mathcal`/`\mathfrak`, functions, spacing, named symbols), which builds up once braces balance and also serves `insert.equation latex` and LaTeX document import (`MathLatexTest`); Wordcraft's per-structure actions (`structure_actions`/`apply_structure`: matrix insert/delete rows and columns, fraction kind, radical degree, n-ary limit location and hiding, delimiter arguments, script add/remove, equation-array rows, group-character/bar flip, remove structure) on the Equation tab's Structure... button and as `equation.edit` `structure:<action>` steps; `#` on Enter numbers a display equation (`E=mc^2#(1)` keeps `(1)` as its number); forced stacked/side limits of gallery templates round-trip (linear text `┬`/`┴` for stacked, a private-use marker for side, OMML `m:limLoc`); all bracket templates (one-sided `├…┤`, `|x|`, `‖x‖`, separators `│`) are real delimiter structures. Math run styles are modeled as in Wordcraft's MRun: `m:sty`/`m:scr`/`m:nor`/`m:lit` and the run's `w:rPr` are kept on each run (stored in the linear text, so they survive editing and typing inside a styled run keeps its style), LaTeX `\mathbf`/`\mathit`/`\boldsymbol`/`\mathsf`/`\mathtt`/`\text` set them, layout and PDF draw bold/italic and the sans-serif/monospace/double-struck/script/fraktur alphabets as Unicode math alphanumerics (as Wordcraft's math_alnum), and LaTeX export names them. `m:phant` is modeled (show/zeroWid/zeroAsc/zeroDesc; `\phantom`, plus `\hphantom`/`\vphantom`, which Wordcraft's math_latex does not read). The n-ary and delimiter Grow toggles (`m:grow`) are modeled, offered as the Grow with Argument / Stretch Brackets structure actions and round-tripped. Wordcraft has no ink math, so none is planned. PDF export draws equation text through the same embedded, subset, shaped font path as body text (bold and italic runs in the bold/italic face), falling back to an installed math face (STIX Two Math, Cambria Math, ...) for math alphanumerics and operators the body font lacks; only the no-font-provider export still uses Helvetica/WinAnsi. With embedded fonts the equation layout used for PDF measures each run with those same faces and fallbacks (the math fallback face included), so printed glyphs fit their boxes; the editor and the no-font PDF path keep base-font widths. Wordcraft itself has no arrow-key entry into an equation and no range selection inside one (Shift+arrows only move), so neither is implemented here. SimulatorUiTest drives the Equation tab, a click into a display and an inline equation, the LaTeX toggle with LaTeX build-up, typing, Up and a structure action in the in-process simulator. See FORMATS.md. |
| Recovery | Crash recovery is stored unencrypted, so password-protected documents get no recovery copy. Wordcraft's recovery is unencrypted too. |
