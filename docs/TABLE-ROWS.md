# Table row sizing and pagination

Table Layout > Cell Size > Row height edits an exact or minimum height in points. Table Properties offers Automatic, At least and Exactly, plus Allow row to break across pages. Row controls apply to the caret's row. Cancel preserves the document; Apply is one undo step and preserves the cell text selection.

Exact heights constrain the shared screen and PDF geometry. Overflowing text remains in the document, but lines below the row are omitted from the display and a partially visible final line is clipped. Returning to Automatic reveals the stored content. Multiple line spacing below single is now accepted (minimum 0.06), retained by native/DOCX storage, and clips to the cell boundary even when glyphs extend below a shorter line box. Exact/at-least paragraph spacing is implemented by the subsequent [line-spacing work](LINE-SPACING.md). Cell vertical alignment applies within the available height. Merged contents can enlarge a flexible row in their span; they cannot enlarge rows whose heights are all exact.

Rows allowing breaks use the available page space. Rows with breaks disabled move to a fresh page when they fit there. Oversized rows still split so pagination can finish; repeated headers reduce the available space on subsequent pages. This is not a complete implementation of Word's row/paragraph/footnote keep constraints.

Height rules and break policy survive native storage, DOCX, row insertion/deletion/reordering, cropping, cell/table splitting and undo. Insert Above/Below inherits the source row's settings. Distribute Rows retains each row's exact/minimum rule and break policy. Existing native files retain their minimum heights and allow breaks. DOCX uses `trHeight` with `hRule`, and `cantSplit`, including explicit false values on import. DOCX heights are rounded to twips; a positive exact height is at least one twip. HTML continues to express row height as a minimum and does not reproduce exact clipping.

The reusable commands are `table.rowHeight {"height":36,"rule":"exact"}` (default rule `atLeast`) and the additional `table.properties` options `rowHeight`, `rowHeightRule` and `allowBreak`. `rowHeight:0` or `rowHeightRule:"auto"` clears the height. These are a subset of Wordcraft's properties API: null-to-clear and a properties getter remain unsupported. Invalid inputs roll back atomically.

The rendered comparison exposed a DOCX export issue: new documents lacked an explicit compatibility mode, causing Wordcraft to use pre-2013 table placement. New exports now declare mode 15, matching the editor's border-at-margin placement. Imported settings are preserved. Legacy compatibility modes are not fully modeled by the editor and can still render differently after import. Wordcraft also adds row insets to specified minimum heights; this app currently treats the minimum as the whole row height. Exact-height comparison does not certify minimum-height equivalence, legacy positioning, complex typography or general rendered parity.

Validation scripts are `table-row-probes.py`, `render-table-row-probe.py` and `live-table-rows-smoke.py`. Accepted results and exact source/binary hashes are recorded in `table-rows-acceptance.json` and the ignored local artifact directory. The reference remains Wordcraft `159b84f54c74e9e82fb3109b758ae7dd6f4e3ab0`; the native framework remains the isolated 008f9ece-based snapshot with recorded Mac fixes. Current-release integration, all-platform acceptance and full parity remain incomplete.

The exact-height PDF fixture has matching row heights and left edges after the compatibility-mode fix. The strict border comparison still fails on a one-pixel right-edge difference at 1200px page height (plus a one-pixel vertical offset). Visual inspection also finds Wordcraft printing the overflow paragraph “third” below the table; this app clips it while retaining the text in the document. These results and the initial nine-pixel placement failure are preserved rather than treating the fixture as full rendered equivalence.

The accepted source passes 462 Java 8 tests, 170 native Mac/iPhone simulator checks, 24 paired row/spacing checks, 174 table regressions and 59 document cases in both readers. Documents and Mailings state were restored exactly and both task-owned native apps stopped. The initial Mac run reopened a window only ribbon-height tall, so its screenshots were rejected and preserved separately. The accepted Mac suite ran with the native window expanded and app zoom at 100%; a new viewport-size guard rejects the undersized setup. Original Mac window size and 214% zoom were restored afterward. Minimum usable desktop window sizing remains a broader UI gap.
