# Live native debugging with Codename One MCP

The `agent-debug` Maven profile starts Codename One's built-in loopback MCP server in the real application. It uses the standard app lifecycle and ParparVM native build. There is no JavaSE UI host or second document session.

```sh
scripts/build-native.sh -Pagent-debug
# Launch the resulting native app, then:
python3 scripts/live-mcp.py tools
python3 scripts/live-mcp.py word_snapshot
python3 scripts/live-mcp.py ui_find '{"label":"Home"}'
python3 scripts/live-mcp.py --screenshot /private/tmp/word-review.png
```

The default port is 18765. Override it at build time with `-Dwordprocessor.agent.port=PORT` and pass the same `--port PORT` to the client. Use a separate port for a concurrently running simulator. The client uses newline JSON-RPC on 127.0.0.1; it does not change the coding agent's global MCP configuration. `--request-file` accepts `{"tool":"name","arguments":{...}}`; `--output` saves the decoded result.

The built-in `ui_snapshot`, `ui_find`, `ui_activate`, `ui_set_text`, and `ui_perform_action` tools operate through Codename One accessibility. Read the current snapshot before using node IDs. `ui_windows` lists native windows; pass its `windowId` to snapshot/find/action tools to address a dialog explicitly. Input to a window blocked by a modal is rejected. Native file pickers and operating-system window controls still require native UI tooling. The framework snapshot used here follows the focused native dialog and returns `pending:true` without a completed `success` result for an action suspended inside a modal dialog, allowing the next call to inspect or dismiss it. Pending means the action has not completed; verify the resulting UI and document.

The app adds three tools:

- `word_commands`: discover the same command schemas used by the editor and CLI.
- `word_snapshot`: inspect live text, selection, tracking settings and a `stateId`; `{"xml":true}` includes the native model XML.
- `word_command`: provide that `stateId`, a `command`, and its `args`. Changes run on the EDT, use the real editor session, share undo/recovery, and refresh the UI. Stale document/selection state and editing while a dialog blocks the document are rejected.

Normal editor jars exclude the opt-in configuration resource, including after a profile switch without `clean`. The explicit profile permits this local development listener in the native Release configuration used for review. Do not use an agent-debug artifact for distribution or performance measurements. The server stops with the app lifecycle. The separately available CLI stdio MCP remains a file-based tool, distinct from this live UI connection.

Validation evidence is recorded in `UI-ACCEPTANCE.md` and `STATUS.md`. Library tests and MCP model edits alone do not establish native input, rendering, mobile, or Wordcraft feature parity.

A reproducible UI acceptance cycle is available for an already open disposable document:

```sh
python3 scripts/live-ui-smoke.py --allow-disposable --output /private/tmp/word-case-review.json
# For the simulator built with -Dwordprocessor.agent.port=18766:
python3 scripts/live-ui-smoke.py --port 18766 --allow-disposable --output /private/tmp/word-case-iphone.json
```

It edits the first paragraph, drives all five case-dialog choices and restores the original XML through undo. On failure it saves partial evidence and leaves the app for inspection. It never overwrites an existing evidence file.


`live-reference-smoke.py` uses the same `--port`, `--allow-disposable` and `--output` arguments. It drives native bookmark add/go-to/delete dialogs, text/page/relative cross-references, reference navigation and Update fields. It restores the starting XML with undo and waits for the visible recovery-saved status before completing. A failed run retains its partial evidence and document for diagnosis; do not terminate the process before restoration has been persisted.


`live-toc-smoke.py` uses the same disposable-document and port arguments for the References TOC workflow. It writes insertion/update screenshots and partial evidence, restores exact XML through undo even after a test assertion fails, and waits for recovery persistence. It navigates mobile ribbon groups from the start so repeated runs do not depend on previous horizontal scroll position. Native keyboard and rendering checks remain separate from MCP command success.


`live-figures-smoke.py` drives Table of Figures, generated-link navigation, caption edits, Update figures, removal and undo. `live-pagination-smoke.py` inserts a longer monospaced fixture and compares page numbers generated by the ribbon with MCP Update fields, then repeats the ribbon update. Both require `--allow-disposable`, accept `--port`, retain partial evidence on failure, restore the exact starting XML, and wait for recovery persistence. These checks include the current document's existing field-bearing headings, which exposed a stale generated-label bug on the mobile fixture.


Note insertion/editing/navigation/deletion acceptance is reproducible with `scripts/live-notes-smoke.py --allow-disposable --output /unique/path/notes.json` (add `--port 18766` for the simulator). It drives real ribbon/dialog accessibility controls, asserts live note objects, restores the exact starting XML through undo, and waits for Recovery saved. Native keyboard checks are separate from these accessibility actions. See `notes-acceptance.json`.


`word_layout` also reports up to 1,000 visible lines: paragraph/block/cell identifiers, character range, display-pixel bounds, point height and optional point clipping height. These values come from the same native layout used by the screen. `live-line-spacing-smoke.py` uses them to assert exact/minimum line geometry through real ribbon/dialog workflows, then restores the original document via undo. Point heights must not be compared directly with pixel bounds without the current display/zoom scale.


The native font workflow is checked by `scripts/live-character-format-smoke.py --port 18765 --allow-disposable --output <new-report.json>`. It uses built-in UI actions to exercise Font controls, verifies minimum checkbox height, cancellation, grouped undo/redo, current-value reopening, mutually exclusive underline modes, hidden-text recovery, clearing and word-at-caret formatting, and restores the exact original XML/recipient state. The eight advanced properties are also available through `format.set`; see [character formatting](CHARACTER-FORMATTING.md).


`scripts/live-text-effects-smoke.py --port 18765 --allow-disposable --output <new-report.json>` exercises all 18 underline choices, color, the four text effects, reopening/cancel/undo/redo and clearing through the actual Font dialog. It scrolls long accessible choice lists without refocusing/resetting their position. It restores original XML/recipient state and waits for recovery persistence. On macOS, `cn1://screen.png` captures the main canvas, not a separate native dialog; treat the dialog control assertions and a desktop screenshot as distinct evidence.
