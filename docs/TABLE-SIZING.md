# Table sizing and insertion

Table Layout exposes AutoFit Contents, AutoFit Window and Fixed Column Width. Table Properties adds preferred width in points or percent, left/center/right table alignment and left-aligned indentation. These are table properties, separate from the existing cell alignment and relative column-width controls.

Contents mode measures styled cell text, field displays, tabs, paragraph/list indents and merged owners. It assigns room between the longest words and complete lines, then updates the displayed widths after cell edits. Window mode starts with equal preferred columns across the text area and redistributes room for longer words. Fixed Column Width freezes the current print-layout widths as an absolute preferred width. Fixed tables retain their proportions when their preferred width changes. Content-driven tables wrap oversized unbreakable text at grapheme boundaries within their available width. Full complex-script shaping and Wordcraft's complete cell-width and style precedence rules remain outside this implementation.

Left alignment uses the stored indentation; center and right align against the section's text area and retain the indentation for a later switch back to left. Tables keep their sizing through row/column edits, row sorting, cell splitting, table splitting, clipboard and undo. Fixed/percentage widths and placement feed the same boxes used by rendering, hit testing and PDF export. Phone reflow scales absolute widths and indentation in a temporary display document; the saved document and printed page geometry remain unchanged.

Native storage retains the sizing model. Existing native files without sizing attributes keep their prior full-width fixed layout. DOCX writes and reads `tblW` (dxa/pct/auto), `jc`, `tblInd` and `tblLayout`; grid/cell widths express the stored preferred proportions. HTML exports preferred sizing and automatic margins. Imported content-driven tables can differ from Wordcraft where explicit per-cell preferred widths or conditional styles govern AutoFit, since those per-cell width constraints are not represented yet. Exact row heights and row-break controls are now covered in [table row sizing and pagination](TABLE-ROWS.md). Table direction, rotated cell text, asymmetric borders/margins, floating tables and nested tables remain gaps.

Ordinary Insert Table now splits at the caret or replaces the selected text, preserves the rich prefix/suffix paragraphs and comment anchors, and focuses the first cell. The Insert dialog's row/column fields are labeled for accessibility and MCP. Cancel is inert; insertion is a single undo step. Body selections spanning paragraphs are supported. The implementation retains a paragraph before and after a table, including an empty prefix at paragraph start; Wordcraft can omit that empty prefix. Nested insertion is rejected. Text replacement participates in Track Changes; the table structure itself is not yet tracked. Existing insertion limits remain 100 rows by 30 columns.

The reusable command surface adds:

- `table.properties {"width":180,"align":"center","indent":18}` for points, or `{"widthPct":60}` for percentages. Omitted properties stay unchanged. These options apply to the table containing the caret/selected cells. Unsupported properties are rejected by the command schema.
- `table.autofit {"mode":"contents"}`, `window` (default), or `fixed`.
- `table.insert {"rows":2,"columns":3}` uses the corrected selection insertion behavior.

Validation and exact build/source hashes are recorded in `table-sizing-acceptance.json` and the local `artifacts/parity-20261017-table-sizing` directory. Paired comparison scripts are `table-sizing-probes.py` and `table-insertion-probes.py`; native scripts are `live-table-sizing-smoke.py` and `live-table-insertion-smoke.py`. Each native script restores the exact starting XML and Mailings state. The accepted candidate passes 447 Java 8 tests, 140 native Mac/iPhone simulator checks, 36 paired sizing checks and 15 paired insertion checks. Regression coverage adds 60 table-layout, 48 formula and 15 Quick Table checks, plus 59 document cases run in both apps. Both task-owned native apps were stopped after restoration.

The reference remains Wordcraft `159b84f54c74e9e82fb3109b758ae7dd6f4e3ab0`. One independently exported, centered 180pt table has matching horizontal raster borders in both PDFs and a one-pixel vertical offset at a 1200px page-height render. This single fixture does not establish general rendered parity. The native builds use the isolated 008f9ece-based framework plus the already recorded Mac fixes. Current-release integration, all-platform acceptance, remaining document workflows and full parity remain incomplete. No performance or source-size superiority claim follows from this checkpoint.
