# Mail merge

The Mailings ribbon uses the same Java command engine as macros and native MCP. Choose **Select Recipients** to paste a list or open CSV, TSV, XLSX, XLSM or ODS. Spreadsheet files offer a worksheet selector and a first-row-header option. **Edit Recipient List** manages inclusion, a single-field filter and a stable text sort; use **Select Recipients > Type or paste a list** to edit the original CSV; **Match Fields** overrides the address-column mappings. Recipient data is session-owned, shares undo/redo and macro previews, and is cleared when opening another document. Save the template and keep the recipient file separately: recipient data is not saved in `.cn1doc`, DOCX or recovery storage.

Insert a merge field, address block, greeting, or rule. **Preview Results**, previous/next recipient and **Find Recipient** resolve fields in the body, tables, headers/footers and notes. Shading is a view setting and is not printed. **Check for Errors** identifies missing recipient columns. **Finish & Merge** creates an editable document for an inclusive record range; Undo restores the template and recipient state. Letters get separate sections/pages and personalized headers/footers. Directory output uses continuous sections. Email mode creates a document; it does not send messages.

Rules support IF, NEXT, NEXTIF, SKIPIF and MERGEREC. Comparisons support `=`, `<>`, `<`, `>`, `<=`, `>=`, using numbers when both values parse as numbers. The supported IF grammar uses one nested MERGEFIELD and literal true/false text. Fields are data; no arbitrary instruction, spreadsheet formula or workbook macro executes. Locked and unrelated fields retain their cached results.

**Envelopes** creates one of eight common envelope sizes, either as a separate document or a section before the letter. **Labels** supports nine Letter/A4 sheet layouts, repeated text, one recipient per label, or a specified row/column. A sheet has fixed product geometry represented by table widths, gaps and row heights. Generation rejects text that exceeds a label's height instead of silently shifting subsequent labels. One sheet is generated; additional recipient sheets and printer-feed calibration remain future work.

The spreadsheet reader handles shared/inline strings, cached formula values, booleans, ISO dates/times, Excel 1900/1904 date systems, sparse cells, ODS row groups and repeats. It does not recalculate formulas, apply arbitrary Excel number formats, preserve workbook formatting, or connect to external data sources. Limits are 64 MiB compressed/inflated package data, 32 MiB per part, 1,000 sheets/columns, 100,000 recipients, 1,000,000 recipient cells and 16 million recipient characters. Malformed and oversized input fails before replacing the current list. CSV supports quoted delimiters, doubled quotes, embedded newlines, comma/semicolon/tab detection, UTF-8 and file-picker UTF-16 input.

Known boundaries: atomic multiline fields still display line breaks as spaces during preview; Finish & Merge emits actual line breaks. Full nested-field evaluation, advanced switches, number/date formatting switches, persistent recipient links, compound filters, multiple sort keys and email delivery are not implemented. Workbook file-picker interactions and physical mobile keyboard/touch behavior are not certified by the MCP tests. Exported field instructions and cached results round-trip through DOCX, but this is not a claim of complete Microsoft Word field compatibility.

Acceptance is recorded in [mailings-acceptance.json](mailings-acceptance.json). Reproduce native checks with `scripts/live-mailings-smoke.py --port PORT --allow-disposable --output NEW_FILE.json` only on an explicitly disposable review document. It restores both original XML and recipient state through undo. Run matched CLI checks with `scripts/mailings-cross-import.py /path/to/wordcraft-cli --out NEW_DIRECTORY`.


## Recipient management

**Edit Recipient List** keeps every imported row. Include/exclude checkboxes use the original source order and show five recipients per page. Include all/Exclude all apply to the entire source list, including other pages and filtered-out rows. Filters and exclusions are combined; clearing a filter does not re-include an excluded recipient. Preview recipient count shows how many rows will merge. Apply commits one undo step; Cancel discards all dialog changes.

Sort by one field uses case-insensitive text order, with stable source order for ties; Descending reverses the text order. This is not numeric or locale-aware collation. Filters support Contains, Equals, Does not equal, Less/Greater than, At most/least, Is blank and Is not blank. Text comparisons ignore case. Inequalities compare finite numbers when both values parse as numbers, otherwise text. Equality keeps leading-zero identifiers distinct. Blank tests ignore surrounding whitespace. One filter is supported; compound AND/OR conditions remain future work.

Preview, previous/next, Find Recipient, label recipients, NEXT/NEXTIF rules and Finish & Merge consume the selected order. The record number and inclusive Finish range refer to that order. Changing the view retains the current source recipient when it remains selected, otherwise selects the first result. An empty result turns preview off and restores field placeholders; Finish rejects an empty list. Restoring all recipients and clearing the filter/sort recovers the original import order. Source rows, mappings, settings and history remain session-owned; none are serialized into a saved template or recovery data.

`mailings.manageRecipients` exposes the same operations to macros and MCP. `mailings.inspect` includes the selected `sourceIndices`, original `sourceRecords`, exclusions and criteria. `mailings.editRecipients` without arguments returns both selected `rows` and original `sourceRows`, plus the source-index mapping. These API indices are zero-based; UI source-row labels and merge range/record numbers are one-based. See [recipient-management acceptance](RECIPIENT-MANAGEMENT.md).
