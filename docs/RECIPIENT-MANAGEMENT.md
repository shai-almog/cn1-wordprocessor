# Recipient management acceptance

Mailings > Edit Recipient List now sorts by one field, filters by one condition, and includes/excludes original source rows. The dialog stages changes, pages through five source rows at a time and previews the selected count. Cancel leaves the session untouched; Apply is one undoable operation. Original data and address mappings survive changes. Preview/navigation, Find, rules and Finish use the selected merge order. Read-only MCP inspection exposes both original and selected rows.

The final Java 8 Maven reactor passes 361 tests with no failures, errors or skips. Five new regression tests cover stable ordering, source identity/current-recipient preservation, numeric/text/blank filters, address mappings, source readback, invalid-input atomicity, empty selections, undo/redo, selected preview/navigation, NEXT rules and DOCX round trips.

The standard Maven/ParparVM Mac and iPhone-simulator builds each pass nine recipient-management checks plus thirteen existing Mailings checks (44 total). The workflows cover paging, Cancel, preview count, sort/filter/exclusions, navigation, selected merge output, restoration after Finish, exclude-all/undo/redo, restoring the original list, numeric and blank filters. Both original XML and recipient state are restored. The task-owned apps are stopped after acceptance. Screenshots confirm desktop and phone labels/layout, including recreated pages. MCP actions do not certify physical input or touch scrolling.

All thirteen existing paired Mailings checks pass against Wordcraft commit 159b84f54c74e9e82fb3109b758ae7dd6f4e3ab0: eleven matched outputs and two DOCX template interchange cases. The new recipient manager is checked against its stated behavior and generated DOCX; these thirteen pre-existing comparisons do not certify its UI as identical to Wordcraft.

Reproduce with `scripts/live-recipient-management-smoke.py --port PORT --allow-disposable --output NEW_FILE.json` on a disposable review session, followed by `scripts/live-mailings-smoke.py` with a fresh output path. The scripts restore original XML and recipient state through undo. Reports, final-source hashes, logs and native bundles are retained under `artifacts/parity-20261016-recipients`.

This batch retains the previous isolated framework snapshot (008f9ece plus the recorded Mac input fixes); it adds no framework changes and does not claim a rebuild against latest master. Early runs retained in the artifact directory include the sandbox graphics-test crash, a UI compile error, a listener-startup race and the corrected row-label styling issue. Final reports and final-build logs are identified explicitly in the acceptance JSON.

Remaining limitations: single-field filtering and sorting only; no locale-aware or numeric sorting, persistent recipient links or saved recipient state. Additional label sheets, multiline atomic preview, advanced mail fields and printer-feed calibration remain incomplete. Current-source Linux/Android/browser/Windows acceptance, physical-device input, cross-cell selections and broader Word fidelity remain open. No performance, binary-size or full-parity claim follows from this checkpoint.
