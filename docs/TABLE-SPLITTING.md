# Table splitting and alternative text

The Table Layout ribbon now provides **Split Cells…** and **Split Table**. Split Cells divides the focused cell into an entered number of equal-width columns, including an ordinary unmerged cell. It refines the underlying grid only where needed; other rows retain their cell extents and content. Existing merged cells retain their vertical span. Original content stays in the first part, new parts are blank, and appearance and paragraph formatting carry into new parts. The 100-column grid limit is checked before committing changes.

Split Table starts a second table at the focused row, inserts an editable paragraph between the tables, and places the caret there. The tables retain column widths, row heights, leading repeated-header rows and alternative text. A vertical merge crossing the boundary is divided between the two tables; its original text stays in the upper table. Paragraph IDs remain stable, so comments follow their original text. New blank subdivisions inherit formatting without copying the original paragraph's tracked revision. Each action has one-step undo and redo, including restoration of the original cell context. Toggling Track Changes now retains the focused table cell, rectangular selection and insertion formatting instead of moving editing back to the body.

Table Properties now edits a table title and description. Each can be changed independently or cleared. Native storage, DOCX `tblCaption`/`tblDescription`, structural edits, table splitting and rich table clipboard copies preserve them. HTML exports accessible labels/descriptions. Visible table paragraph accessibility nodes expose the title, row/column location and description. This checks exposed semantics, not full VoiceOver/TalkBack navigation. The native mobile screenshot retains a missing-glyph rendering for the map emoji even though its Unicode value survives editing and storage; font fallback remains incomplete. Text is capped at 10,000 Unicode code points per field, matching the pinned reference. XML attribute whitespace is encoded as character references so multiline descriptions survive standard readers.

The same operations are available to macros, CLI and built-in MCP:

- `table.split {"columns":3}` operates on the focused cell; the default is two. Explicit `block`, `row` and `column` coordinates must be supplied together. For compatibility, explicit coordinates without `columns` retain the older unmerge operation.
- `table.splitTable {}` splits before the focused row (or first selected row). Splitting before the first row is rejected atomically.
- `table.altText {"title":"Quarterly sales","text":"Revenue by region"}` edits metadata. Omitted fields are retained; empty or whitespace-only strings clear a field.

Validation: 409 Java 8 tests; 34 native checks each on Mac and iPhone simulator; 20 paired splitting checks, 20 paired alternative-text checks, 60 table-layout regressions and 59 paired document cases. Original documents and recipient data were restored and both review applications stopped. Exact artifact provenance is in `table-splitting-acceptance.json`. Reproduce the native UI flows with `scripts/live-table-splitting-smoke.py` and `scripts/live-table-alt-text-smoke.py`. Paired CLI/DOCX coverage is in `scripts/table-splitting-probes.py` and `scripts/table-alt-text-probes.py`. The initial multiline-attribute failure and earlier UI-test selector failures are retained separately from passing final reports.

Boundaries: these controls split the focused cell horizontally; arbitrary row subdivisions or splitting every cell in a selected rectangle are not implemented. Splitting a cell into one column does not unmerge it; the legacy unmerge action remains in Rows and Columns. Nested tables, table auto-fit modes, text rotation, exact row heights, asymmetric borders, RTL visual table order, table formulas and advanced table styles remain gaps. The pinned reference sometimes divides an existing multi-column span along unequal old grid lines; CN1 instead honors equal physical widths. The paired cases cover ordinary cells, subdivision of a merged cell into more columns, and table boundaries; they do not establish complete rendered equivalence.

The native artifacts use the existing isolated 008f9ece-based framework snapshot and local Mac patches. Latest released-framework integration and current-source Windows, Linux, Android and browser acceptance remain separate work. Full Wordcraft parity and matched final performance measurements are not complete.
